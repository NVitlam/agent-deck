~/what-is-it

Live observability for AI coding agents.

In plain words: a live tree of your agents and their tool calls, right inside VS Code.

  • vs code extensionFree and open source (MIT). Install it from the VS Code Marketplace.
  • works withClaude Code, Codex and OpenCode. You run them as usual; Agent Deck only watches, and shows their sessions side by side in one panel.
  • session filesReads the files your agents already write to your disk as they work.
  • hooksOptional. Claude Code and Codex hooks ping it on 127.0.0.1 when an agent starts or a tool finishes. You paste them in yourself.
~/problem

Your agents work in parallel. Your terminal shows one line at a time.

Give Claude Code or Codex a big task and it splits the work across several agents running in parallel. In the terminal you can barely see who's doing what, who's stuck, or why it's taking 10 minutes. The logs exist, but as raw files nobody reads while the work is running.

"I built Agent Deck because I couldn't understand what was running on my own machine."

Nadav Vitlam, creator

~/where-it-sits

On the side, reading. Never in the way.

Agent Deck isn't in your terminal and isn't between your agent and the API. It reads the files your agent already writes, listens to hooks, and draws what it reads.

  • readsThe session files your agent already writes to disk, as they grow. Read-only.
  • listensOptional hook signals you paste into your agent's settings, sent to 127.0.0.1 only.
  • neverSits in the API path, wraps or steers your agent, writes to its files, or sends anything out.
~/who-its-for

For developers who hand agents long tasks.

Solo developers and small teams who give Claude Code, Codex or OpenCode long tasks with subagents. It isn't a management dashboard and it isn't enterprise monitoring.

  • seeing firstThe point is seeing what's happening: who's working, who's stuck, where the time goes.
  • tokens secondTokens and cost are shown too. Even on a subscription they help you stay inside your usage limits.

~/faq
What does "observability" mean here?

Not OpenTelemetry. It's closest to live traces: a tree of agents and tool calls, with the time and token count on each one. There's no log export and no Grafana metrics. It's a local, live viewer, not monitoring infrastructure.

Is this about saving tokens?

Mostly not. The main point is seeing what's happening. Tokens and cost are shown, and they help with usage limits, but they come second.

Can it control my agents?

No. It only watches.

Does it send my data anywhere?

No. It makes no network calls at all.

Why do I paste the hook myself?

Because read-only includes your settings. Agent Deck never writes to them.

What are the limits?

The session file format is undocumented and changes between versions. When it changes, Agent Deck refuses to draw rather than guess, so an agent update can break it until I fix it. It's a one-person project, and it's early.

See the compatibility details in the README.
