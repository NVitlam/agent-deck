## Model provenance, and why it is not the anchor

The model each run used is recorded above because this corpus is **fixture law** (G6) and a
later reader is entitled to know what produced it.

**The fingerprint does not read the model string.** G9 anchors provenance on
`session_meta.payload.cli_version` alone, so changing model does not move the corpus anchor
and cannot make an unsupported version supported.

It is recorded for a second reason, which is not cosmetic: Codex ships **two multi-agent
toolsets** and hands a session one of them **by model**, at one `cli_version`. A `v2` model
(`collaboration` namespace) produces `task_name` and a populated `agent_path`; a `v1` model
produces neither and joins its children by id instead (`output.agent_id`), so both dialects
graft — only the key and the node label differ. Every run DECLARES its own dialect at
`turn_context.multi_agent_version`, so nothing has to be inferred from a model name. The
earlier anchor corpus was produced by `gpt-5.6-terra`.

## What was filtered out of the hook streams, and why

Both engines POST hook events to **one** loopback listener (D0.3), and a Claude Code hook
block on the same machine is live and unconditional. Records not carrying the Codex
discriminator are dropped at this boundary, counted, and reported — never silently. A run
whose stream is mostly foreign is refused outright rather than filtered.

The dropped records are retained under `lab/` as witness data, because real Claude Code
payloads arriving on the shared port are exactly what the Phase 3 listener-discrimination
test needs. They never cross into `fixtures/`: they carry real developer paths.
